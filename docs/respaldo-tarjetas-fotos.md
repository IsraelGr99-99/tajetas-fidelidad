## Procedimiento seguro

Ejecutar desde la raíz del repositorio, en PowerShell. Confirmar primero que el proyecto enlazado es **el de pruebas**, no producción. No poner contraseñas ni cadenas de conexión en el historial de comandos o en capturas.

1. Consultar `supabase migration list --linked`. Deben figurar como pendientes únicamente `20261030100000_loyalty_card_branding.sql` y `20261030110000_fix_storage_photo_path_scoping.sql`. Si el historial no coincide, detenerse y revisar; no usar `db reset`, `migration repair` ni `--include-all` para forzarlo.
2. Crear `.local-backups` si no existe. Generar nombres nuevos `pre-card-photos-<fecha>-schema.sql`, `pre-card-photos-<fecha>-data.sql`, `pre-card-photos-<fecha>-storage-schema.sql` y `pre-card-photos-<fecha>-storage-data.sql` sin sobrescribir archivos previos. La carpeta está ignorada por Git; restringir su acceso porque los datos pueden contener información personal.
3. Respaldar la base con `supabase db dump --linked --file .local-backups/pre-card-photos-<fecha>-schema.sql` y `supabase db dump --linked --data-only --use-copy --file .local-backups/pre-card-photos-<fecha>-data.sql`. Exportar también esquema y metadatos de Storage con `supabase db dump --linked --schema storage --file .local-backups/pre-card-photos-<fecha>-storage-schema.sql` y `supabase db dump --linked --schema storage --data-only --use-copy --file .local-backups/pre-card-photos-<fecha>-storage-data.sql`. Confirmar que cada comando termina sin error y que los archivos no están vacíos. Si la CLI omite el esquema administrado aun indicándolo, detenerse y obtener un respaldo o inspección de sus políticas por otro medio antes de aplicar la migración.
4. Recordar que el SQL de Storage **no incluye los bytes de las imágenes**. Si se necesita una recuperación completa de archivos, copiarlos por separado con la API/CLI de Storage antes de intervenir; no tratar el SQL como un respaldo completo de fotos.
5. Ejecutar `supabase db push --linked --dry-run` y comprobar la lista exacta de migraciones. Si aparecen otras migraciones pendientes, detenerse. Aplicar con `supabase db push --linked` únicamente cuando el listado sea el esperado.
6. Repetir `supabase migration list --linked` y probar con owner autenticado: guardar diseño y logo de tarjeta; crear un producto con foto; reemplazar y quitar la foto. Comprobar en caja la miniatura. Nunca marcar la aplicación como terminada solo porque los archivos locales o las pruebas PGlite pasaron.

Los comandos de respaldo son exportaciones, no restauraciones. Restaurar datos sobre una base con actividad requiere un plan separado para evitar sobrescrituras y duplicaciones.
